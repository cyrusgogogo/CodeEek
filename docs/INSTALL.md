# 安装、升级与排障

当前 **dsh-code-reading 0.1.8 归档**适用于 **DSH 0.2.1-rc.3**。普通使用者安装预构建 tarball 即可，**不用先安装 Node、pnpm、React 或运行项目构建**。本插件不自带模型，请在 DSH 中配置模型提供方。

> 从 [GitHub Release v0.1.8](https://github.com/cyrusgogogo/dsh-codeeek/releases/tag/v0.1.8) 下载安装包、SHA256 校验文件和发布报告。旧 `0.1.7` 仅适用 rc.2，不能改名或使用豁免代替升级；源码构建不会更新已安装的 DSH。

- [五分钟开始阅读](<USAGE.md>)
- [功能、只读边界与资源上限](<../README.md>)

## 1. 先确认安装目标

1. 安装 `0.1.8` 归档前，在你实际使用的 DSH 中查看版本，确认目标为 `0.2.1-rc.3`。`engines.dsh`、peer 与自检是兼容性声明，不代表已测试其他 DSH 版本；不要对不兼容版本盲目授予豁免。
2. 使用 **当前应用对应的插件／Bundle 安装管理界面**。桌面应用和 CLI 使用不同的安装/profile 管理层；不要用 CLI 去管理桌面版保留的 profile。
3. 使用可信的 `dsh-code-reading-0.1.8.tgz` 及同次发布的 SHA256 文件。不要把源码目录、Git 地址、单个 Client 文件或旧包改名当作新版本安装。
4. 升级前停止当前阅读轮次，备份阅读档案目录，并保留原安装包。插件不会自动删除或迁移档案。

本插件通过 bundle 新增一个 `code-reading` Host 行，由它携带 Client；不替换普通编码 preset、不覆盖你的工作区配置。

## 2. 检查归档（推荐）

如果已经有可信的校验文件，可在源码仓库根目录使用 PowerShell：

```powershell
$archive = (Resolve-Path '.\releases\dsh-code-reading-0.1.8.tgz').Path
$expected = ((Get-Content -LiteralPath "$archive.sha256" -Raw).Trim() -split '\s+')[0]
$actual = (Get-FileHash -LiteralPath $archive -Algorithm SHA256).Hash
if ($actual -ne $expected) { throw '归档 SHA256 不匹配，请停止安装并重新获取可信发布包' }
$archive
```

最后一行打印的是可交给安装器的绝对路径。**SHA256 证明字节一致，不是发布者签名，也不能让不可信来源变可信。**

开发者可进一步运行：

```powershell
pnpm run verify:package -- releases/dsh-code-reading-0.1.8.tgz
```

该命令直接有界读取 gzip/tar，检查包内入口、共享 chunk、skill、原生 Client 工厂、文档、版本及逐文件哈希；不解压、不执行包内代码、不接入正在运行的 DSH。它不能代替安装后的验收。

## 3. 安装、启用与生效

1. 在 DSH 插件／Bundle 管理中选择安装本地归档，填入上一步得到的 **绝对路径**。
2. 确认安装的是 `dsh-code-reading@0.1.8`，并在当前应用/profile 中启用。仅把依赖装进某个目录，不等于 bundle 已启用。
3. 读取安装器返回的应用状态：

   | 结果／现象 | 应做什么 |
   | --- | --- |
   | `restart-required` | 保存成功但当前 Host 可能仍是旧版。停止正在运行的任务，**完整退出 DSH，再重新打开**；桌面版有托盘驻留时也要真正退出。仅刷新网页不足以重启 Host。 |
   | `applied` | 安装器报告已应用。仍需检查入口与版本；必要时刷新 Client 页面。 |
   | Host 已更新、页面仍旧／没有新入口 | 刷新当前 DSH 页面。若仍异常，确认 bundle 启用和安装目标，不要另起服务器。 |
   | 安装失败／版本不匹配 | 先保留原配置与旧包，按错误处理；不要一律批准构建脚本或版本豁免。 |

4. 在左侧工作区列表上方找到 **阅读代码**，打开后点击 **安装与使用**。
5. **成功标志**：页面显示阅读插件已连接、项目列表加载完成；展开 **连接排查与版本信息** 可核对 Client `0.1.8`、Host `0.1.8` 与版本一致提示。目标 DSH 标签是兼容性声明，**不是对当前应用版本的自动检测**。
6. 再按 [使用手册](<USAGE.md>) 配置模型、绑定仓库、开始阅读。安装、打开页面、创建项目都不会自动发起模型阅读请求。

包没有 `preinstall/install/postinstall/prepare` 安装期脚本；`prepack` 只在开发者打包前进行离线检查。预构建包已包含运行代码和前端依赖，不需要让安装器现场编译 Mermaid 或安装另一份 React。若安装器要求意外的构建权限，应先核对包与依赖来源。

## 4. 数据目录与备份

优先级由高到低：

1. Host 配置 `dataDir`。
2. Host 进程环境变量 `DSH_CODE_READING_HOME`。
3. Host 进程环境变量 `DSH_HOME` 下的 `code-reading`。
4. 当前 OS 用户主目录下的 `.dsh/code-reading`。

自定义 Host 配置对象示例：

```json
{ "dataDir": "D:\\DSHData\\code-reading" }
```

以上是**该插件的配置对象**，不是替换整份 DSH 配置的文件。若使用 patch，请保留其他行与所需字段；DSH patch 对 `config` 的覆盖是整份替换，不是深合并。

- 自定义目录和环境变量必须是非空绝对路径，Windows 必须包含盘符（如 `D:\DSHData`），不接受 `\reading`、`/reading` 或 UNC；不会自动展开 `%USERPROFILE%`、`~` 等字面量，也不要填写相对目录。配置错误会明确拒绝启动，不会悄悄把数据写到安装 CWD。
- 修改环境变量后要让 **DSH Host 进程**重新继承它；仅在另一个终端设置变量、或刷新网页，不会更改现有桌面进程的环境。
- 改变已运行 Host 的数据根需要完整重启。**不会自动复制、合并或迁移旧目录**；想继续旧项目时应保留原根。迁移或备份应先停止阅读、完整退出 DSH，再操作整个档案目录。
- 不同 profile 如果希望隔离数据，必须显式选择不同的绝对目录；默认目录可能共享。
- 源码目录和档案目录必须互不嵌套；不要把整个用户主目录或含档案目录的上层目录绑定为仓库。
- “安装与使用 → 诊断信息”可查看实际档案根和来源。分享前可遮去目录中的用户名；诊断不包含源码、对话或密钥。

阅读档案不是 DSH 自身 Session 日志的替代备份。两者恢复职责不同；笔记和最终消息可能包含源码片段，应按项目敏感级别保护。

## 5. 升级、停用、卸载与回退

**升级**：停止当前轮次 → 备份档案与保留旧包 → 安装新版本归档并启用 → 按 `restart-required` 完整退出重开 → 刷新 Client → 检查 Host/Client 版本及原项目列表。0.1.8 是面向 DSH `0.2.1-rc.3` 的兼容版本，包含新版工作台、方法级阅读与项目地图；保留旧档案，无需自动迁移。0.1.7 是面向 DSH `0.2.1-rc.2` 的兼容版本：同步精确宿主目标并重新构建，保留 0.1.6 的阅读工作台、档案格式与批注侧车格式，不自动迁移旧档案。0.1.6 是阅读工作台改版（目标 `0.2.1-rc.1`）：新增按会话保存的阅读位置、源码联动与 `reader-state` 接口，不改变 0.1.4／0.1.5 的 state 或批注侧车格式。0.1.5 是面向 DSH `0.2.1-rc.1` 的兼容修复；0.1.4 首次保存批注时新增会话内 annotations.json 侧车，回退更早版本会忽略批注，不会自动删除侧车，应连同整个会话目录一起备份。

如果升级 DSH 后旧插件被标记为不兼容，请先取得并验证**与当前 DSH 匹配的新版本归档**，再按管理界面提示卸载旧插件、安装新版，不要启用兼容性豁免。卸载不删除阅读档案；继续使用相同数据根即可恢复原项目。0.1.4 的目标是 DSH `0.2.0-rc.2`、0.1.6 的目标是 DSH `0.2.1-rc.1`、0.1.7 的目标是 DSH `0.2.1-rc.2`，都不要在 DSH `0.2.1-rc.3` 上直接回退。

**不要覆盖或改写旧版本归档。** 安装器可能仍引用原文件；同版本内容变化会破坏本地完整性。发布脚本会在构建前拒绝覆盖同名包、校验文件或发布报告，要求提升版本，或选择新的测试输出目录。

**停用／卸载**：使用当前 DSH 的插件管理入口并按提示重启。Client 入口和 Host 注册应随生命周期撤销；遗留阅读工具与排队准入请求会拒绝继续执行。已开始的操作不承诺回滚；应先停止当前轮次。停用／卸载不会删除阅读档案，也不自动删除 DSH 原生日志。

**重新启用**：沿用同一数据目录可继续原档案；同一 Host 根复用 store 与锁。不要同时启动两个独立 DSH 进程写同一档案根，本插件没有跨进程文件锁保证。

**回退**：停止阅读并备份后，通过安装器重新安装保留的旧版本，按提示重启和刷新。跨版本数据兼容性应先在备份副本中确认；不要用手工改包名／覆盖 tarball 的方式回退。原 0.1.1 的包内说明可能漏写完整重启要求，以本页的 Host 重启步骤为准。

## 6. 按症状排查

| 症状／错误码 | 检查与恢复 |
| --- | --- |
| 已安装但没有“阅读代码” | 确认当前应用/profile、bundle 已启用；按安装器要求完整退出重开；再刷新当前页。检查 DSH 插件诊断中的待注入服务或启动错误。 |
| `HOST_UNAVAILABLE` / 404 / 405 | 页面存在但 Host 路由未就绪。确认启用并按要求重启 Host；不要另开替代 Web 服务。 |
| `VERSION_MISMATCH` | 新 Client 配旧 Host，或相反。确认安装版本，完整退出重开并刷新；就绪检查通过前不会开放创建和发送。即使版本号相同，也可能是不同构建；当前源码的 Client 还会检查 Host 是否声明仓库移除与默认阅读模型能力。 |
| 删除仓库提示 `UNKNOWN_METHOD`／Host 不支持仓库移除 | 当前响应的 Host 不认识删除接口，本次删除未执行。确认当前应用/profile 安装的是包含该功能的 Host，再完整退出 DSH（含托盘驻留）并重开、刷新页面。若重启后仍不支持，检查当前应用/profile 实际启用的包及 Host 加载错误，并更新到包含该功能的新版本；旧的 0.1.7 发布归档不会因源码构建而改变。不要手动删除源码或阅读档案。 |
| `AUTH_REQUIRED` / 401 / 403 | 当前 DSH 登录／认证已失效，重新登录当前页面。不是要求授予源码写权限。 |
| `PROTOCOL_ERROR` / HTML 响应 | 当前连接返回了非插件 JSON 或畸形协议。刷新、检查 Host/Client 一致性和插件状态；页面不会显示原始 HTML 内容。 |
| `NETWORK_ERROR` | **请求结果未确认**。先恢复连接并刷新，看项目、会话和对话是否已存在；不要连续重复创建或发送。请求助手不会自动重放变更。 |
| 项目列表／档案加载失败 | 点击相应只读重试；不会重新发 prompt，不删除已有档案。 |
| 没有模型／提供方暂不可用 | DSH“设置 → 模型”配置与检查提供方，再到“阅读设置”点“重新加载”。旧会话模型不会因目录刷新而自动切换。 |
| `DEFAULT_MODEL_UNAVAILABLE` | 插件默认或本会话局部模型当前不可用；在“阅读设置”重新加载后更改或清除覆盖，不会自动换成其它提供方。默认设置只影响新建阅读，不修改已有会话或 DSH 全局默认。 |
| `STALE_READING_SETTINGS` / `READING_SETTINGS_CHANGED` | 默认模型设置已变化，先重新加载核对；不自动重放保存。 |
| `READING_SETTINGS_CORRUPT` | 只有默认设置文件损坏，旧档案仍可浏览；设置页可明确“重置默认模型”。链接、身份、预算及 UTF-8 错误不会作为普通损坏自动重置。 |
| `MODEL_CHANGED` | 实际会话模型与页面确认值不一致。刷新并重新确认提供方，不自动改成全局默认。 |
| `DeepSeek Messages stream: tool input is invalid JSON` | 模型返回的工具参数字符串不是合法 JSON，DSH 在执行该工具前拒绝本轮响应；不是要求修改被阅读的源码 JSON 文件。先刷新核对知识点／运行状态，再手动发起一次新轮次；可要求保留已有证据、精简归档正文、正确转义英文双引号／反斜杠／换行。插件已加强输出约束，但不能保证模型永不生成坏 JSON；不会猜修参数或自动重发。反复发生时保留日志中的错误码和工具名排查，不分享密钥或整份源码日志。 |
| `INVALID_DATA_DIR` / `READING_ROOT_CHANGED` | 修正非空绝对目录；若改变数据根，完整退出重启，不会自动迁移。 |
| `READING_UNAVAILABLE` | Host 已停用或更新。检查插件状态；旧 handler 与旧排队请求不会借新实例继续执行。 |
| `STORAGE_OVERLAP` / `DUPLICATE_REPOSITORY` | 重新选择互不嵌套、互不重复且与档案分离的真实本地仓库。 |
| `LINK_DENIED` / `FILE_ALIAS` | 仓库或目标是符号链接、junction／硬链接等不支持的别名，改用独立的真实源码副本。 |
| `STALE_REVISION` / `STALE_EVIDENCE` | 刷新阶段、重新读取源码取证；旧证据不会静默套到新代码上。 |
| 搜索截断、文件没有找到 | 缩小路径范围或指定已知入口；达到扫描预算时“未检出”不代表“不存在”。 |
| `AUDIT_CORRUPT` / `ARCHIVE_GAP` | 保留原档案和 DSH 日志，停止继续写入或新建阅读会话；不要手动补造审计记录。 |

## 7. 源码开发路线（不是普通安装步骤）

推荐 **Node.js 24 LTS / pnpm 11.7.0**；包最低 Node 声明为 `>=22.18.0`。完整日志回归额外要求运行时提供 zstd。浏览器验收默认使用本机 Chrome，可通过 `DSH_TEST_BROWSER` 指定可信 Chromium 的可执行文件。

```powershell
pnpm install --frozen-lockfile --ignore-scripts
pnpm run check
pnpm run doctor -- --dsh-version 0.2.1-rc.3
pnpm run pack:release
```

- `check`：构建 → 所有单元／接线测试 → 网络全拦截浏览器测试 → 离线 doctor。
- `doctor`：不写用户数据，不读取用户 DSH 配置；只校验本仓库构建、源码新鲜度和显式提供的版本字符串，不声称探测到了运行中 DSH。
- `pack:release`：先拒绝覆盖 → 构建 → 全部回归与隔离浏览器 → 源码新鲜度检查 → 暂存打包 → **真实 tarball** 静态校验 → 本次自身可信包的隔离导入／模拟接线／Client 浏览器复验 → 发布归档、`.sha256` 和 `.release.json`。
- `test:package`：可用 `pnpm run test:package -- --trusted releases/dsh-code-reading-0.1.8.tgz` 重复验收自己信任的本仓库归档。**会解包并执行包内代码**，不用于未知第三方包；未知包只用无执行的 `verify:package`。两者都不安装到当前 DSH。
- 需要重复演练同一版本时，可用 `pnpm run pack:release -- --out-dir .test-output/release-check-1`。目录须真实位于仓库内，祖先不能是 symlink／junction；不接受源码、依赖或 `lib` 等包运行目录，目标文件仍不可覆盖。路径检查不是抵御同账户恶意并发目录替换的 OS 沙箱。
- 常规 `pnpm pack` 的 `prepack` 只检查已有构建，不隐式编译；干净源码／过期构建会明确失败。官方分发入口是验证后的预构建 tarball，不承诺直接 Git 安装。
- 修改源码后必须重新构建、发布新版本、安装并按要求重启／刷新；本插件源码不是当前 GUI 的 dev server，不承诺自动热更新。

所有这些自动测试都是隔离验收，**没有安装到用户 DSH、没有真实模型请求、没有真实登录 GUI 端到端验收**。真正安装成功还要完成第 3 节的版本与入口检查。
