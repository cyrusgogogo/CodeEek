# 阅读代码 0.1.4 · 文件工作台与批注验收

## 交付范围

这是独立插件升级，不修改 DSH 核心，也不改写用户绑定仓库。新增插件内第三栏：右侧“文件目录 / 批注”，中间“文件阅读”只读打开普通 UTF-8 文本。复用类型识别、语法高亮、真实行号、折行与分页；HTML、SVG、脚本仅作为源码文本，不作为网页执行。

选区可用右键或 Shift+F10 打开菜单：交给当前已确认模型分析，或新增本地批注。分析继续沿用阶段、模型、取证和请求幂等准入；原五工具白名单不变，模型没有批注确认或重新绑定工具。

## 源码变化：不把位置匹配当作批注仍然正确

每条批注保存仓库 ID、相对路径、原字节 SHA256、UTF16 起止位置、精确选文和双侧上下文。不是只记一个行号，也不是整文件备份。

| 情况 | 行为 |
| --- | --- |
| 本次读到同一文件哈希，且没有待复核记录 | 展示本版本已确认位置及行边标记。 |
| 文件哈希改变，但原选文与上下文能可靠唯一匹配 | 仅给候选位置，等待人工复核，不显示已确认行标。 |
| 选文或上下文改变、可靠匹配不唯一、文件不存在／不可读 | 保留历史选文，不猜旧行号；由用户选择当前代码重新绑定。 |
| 观察过变化后又回滚到旧字节 | 仍需人工确认，不自动恢复已确认。 |
| 用户确认或重新绑定 | 增加绑定历史版本，保留原记录。 |

保存位置：阅读会话自己的 `annotations.json`，随整个阅读目录备份；汇总 Markdown 导出包含批注。该侧车包含选区及附近代码，可能敏感，不是加密保险库。存储坐标为 1 起始行、0 起始 UTF16 列、末端不含；界面列转换为 1 起始显示。换行规范为 LF，原文件哈希仍按原始字节计算。

### 生效步骤

1. 保存当前工作，完整退出 DSH（有托盘驻留时也要真正退出）。
2. 重新打开 DSH，再打开“阅读代码 → 安装与使用”。
3. 确认 **Client 0.1.4 / Host 0.1.4**、版本一致、原项目列表正常；仅刷新网页不足以重启旧 Host。
4. 打开阅读会话，右侧“文件目录”选择文件；选区右键或 Shift+F10 分析/批注。远程模型会接收你明确发送分析的代码和取证上下文，手动批注不自动外发。

## 明确边界

- 工作台打开文件时先记录已读到的变化，再检查页范围；旧页码越界也不会丢掉复核标记。观察指批注工作台已保存的版本观察，不是 Git 历史或所有外部进程的读写日志。
- 没有实时文件监听或 Git 世系／重命名猜测。重新打开、重新加载文件或刷新批注时检查；提交分析/批注前 Host 还会核验。未观察到的同字节删除重建不能识别。
- 哈希只证明该文件版本，不证明其他依赖或业务语义未变化。候选永远不自动确认。
- 只支持一个 Host 写同一档案根；进程内锁不等于跨进程事务。侧车原子清单与提交凭据是权威，JSONL `*-attempt` 仅表示尝试；开始原子 rename 的提交点不提供撤回保证。
- 单文件 1 MiB，阅读页最多 200 行，选区最多 8,000 UTF16 单位；每会话最多 100 条批注、400 次人工提交、8 MiB 侧车，每条最多 20 个绑定版本，正文最多 4,000 字符。
- 本轮不重放真实阅读档案、不发真实模型请求，不以隔离夹具代替登录 GUI 的最终验收。没有启动替代服务器，也没有替用户自动退出 DSH。
