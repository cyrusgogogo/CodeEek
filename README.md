# 阅读代码 · DSH 独立插件

一个独立于普通工作区选择的代码阅读模式：先理解业务，再梳理调用链、精读实现，最后通过具体场景验证理解。

- **独立入口**：侧边栏“阅读代码”，位于工作区列表上方，不替换原工作区或对话入口。
- **多仓库项目**：一个阅读项目绑定 1–12 个本地仓库。绑定不可变，切换普通 DSH 工作区不会改变阅读目标；添加仓库时新建项目。
- **五阶段互动**：发现业务 → 业务解释 → 调用链 → 代码精读 → 理解验证。阶段和主题由用户选择，不自动推进；每轮只发布一个知识点。
- **代码证据**：仓库 ID、相对路径、行号、SHA256、符号文本线索与读取时间；打开证据和发布知识点时重新核验，源码变化会使旧证据失效。
- **固定留痕**：读取审计、阶段历史、知识点 Markdown、Mermaid 原文、最终对话文本与汇总导出。
- **Mermaid**：支持时序图、流程图、类图、状态图、ER 图；危险指令与资产节点在渲染前拒绝，SVG 清洗后在禁止脚本的 iframe 中展示。

## 使用

1. 在 DSH 左侧点击 **阅读代码**。安装器如提示 `restart-required`，需完整退出并重新打开 DSH（不只是刷新页面）；仅 Client 入口未更新时才刷新当前页面。
2. 点击 **新建阅读项目**，设置名称，从已有 DSH 工作区添加仓库，或选择本地绝对目录。仓库不能与产物目录重叠，也不能在同一项目中重复或互相嵌套。
3. 确认页面底部显示的**会话模型／提供方**。远程模型会接收本轮读取的代码与对话；本插件不提供本地模型运行器。
4. 点击 **开始本阶段阅读**。导师会有限检索真实代码、提供业务主题并归档当前知识点，然后等待你决定。
5. 选择主题，切换阶段，点击深入问题，或者输入自己的问题。建议先回答“理解验证”的场景，再继续下一点。
6. 在 **代码与证据** 中浏览／搜索仓库，或点击知识点里的证据按钮。旧证据不会静默指向修改后的代码。
7. 在 **对话留痕** 中查看最终消息，在 **产物与规则** 中查看固定目录；**导出档案**会把知识点、绑定与证据索引汇总为 Markdown。

普通 DSH 侧边栏切换工作区不会重绑仓库。重新打开本页面可以继续原阅读会话。暂停／停止只终止当前轮次，不删除档案。

## 只读与信任边界

阅读 Agent 只拥有以下五个专用工具：

| 工具 | 能力 |
| --- | --- |
| `reading_catalog` | 查看项目、绑定、当前阶段与主题 |
| `reading_files` | 有界枚举文件 |
| `reading_search` | 有界字面量搜索，不执行正则表达式或项目代码 |
| `reading_read` | 通过只读文件句柄读取有限行范围并创建证据 |
| `reading_publish` | 向固定目录发布一个结构化知识点并结束本轮 |

Host 根执行守卫与被保留的 preset 守卫共同拒绝 shell、通用文件写入、网络工具、子代理、工作流及插件转调。即使在普通权限界面选择更宽模式，也不能为阅读 Agent 放行这些工具。框架自身的模型调用不属于被禁止的工具网络访问。

受控产物由 Host 写入；Agent 不能指定产物文件名或任意写入路径。源码根与产物根绑定时检查分离，拒绝符号链接／junction、硬链接、路径穿越、UNC、ADS 和设备路径。扫描会跳过依赖／构建目录及部分常见敏感文件名；**这不是通用秘密检测或 DLP**，仓库内其他普通文本仍可能包含敏感信息。

**重要限制：这是插件工具边界，不是操作系统级沙箱。** 同一账户的其他本地进程如果能在路径检查与实际操作之间并发替换目录，纯 Node.js 路径 API 不能提供原子目录句柄约束。本插件不宣称能抵御这种恶意本地文件系统竞态，也不阻止其他普通 DSH 会话修改同一仓库。请使用可信、权限受控的产物目录；不支持把不受信任的并发本地写入者纳入“严格只读”保证。需要该保证时，应额外使用 OS ACL、只读挂载或独立容器。

证据表示“某时刻实际读取到这些字节”，不是跨文件／跨仓原子快照，也不等于 AI 结论必然正确。符号定位为文本匹配，不是 AST 解析或静态调用图。请核对事实、推导与假设标注。

## 固定目录

默认根目录：

```text
%DSH_HOME%/code-reading
# 未设置 DSH_HOME 时：%USERPROFILE%/.dsh/code-reading
```

可通过 Host 配置 `dataDir`，或环境变量 `DSH_CODE_READING_HOME` 指定；改变已有运行时的根目录需要重启 DSH。不同 DSH profile 若希望隔离阅读档案，应使用不同 `dataDir`。

```text
code-reading/
  projects/<project-id>/
    project.json
    sessions/<reading-id>/
      state.json
      audit.jsonl
      notes/<lesson-id>.md
      diagrams/<lesson-id>.mmd
      messages/<dsh-event-seq>.json
      exports/reading.md
```

- `audit.jsonl` 留存操作、仓库／路径、范围、哈希和时间；不保存源码全文或原始搜索词。
- `messages/` 保存用户和导师的最终文本，不保存隐藏推理或所有工具结果。DSH 原始 Session 日志仍按 DSH 自身规则保存在原位置。
- Mermaid 内嵌代码块保存在知识点 Markdown 中；通过结构化 `mermaid` 字段发布时，会额外生成独立的 `.mmd` 文件。因此没有独立图文件不一定表示图源码未归档。
- 笔记与最终消息可能包含源码片段。目录不是加密保险库，请按项目敏感级别管理访问、备份与保留周期。
- 不自动删除档案，不宣称跨文件事务完全原子。消息归档失败会显示错误，随后重放完整连续 DSH 事件前缀；孤立的失败发布临时文件不能被当成已提交知识点。

## 资源限制

当前版本仅支持本地、非链接、UTF-8 普通文本文件：

- 单文件最多 1 MiB；单次最多 400 行、100,000 字符。
- 文件枚举最多访问 8,000 个条目；搜索最多 2,000 个文件、16 MiB、80 条命中；达到上限会标为截断。自定义依赖缓存目录可能占用预算；遇到截断时可指定已知入口文件路径直接读取，不能把“未检出”当作“不存在”。
- 单会话最多 500 条证据、100 个知识点、2,000 条最终消息；审计／状态文件上限 8 MiB。到限后应新建阅读会话。
- Mermaid 最多 10,000 字符、160 行、120 条边；不支持 HTML、链接／点击回调、图片／图标资产、初始化配置或自定义 CSS。
- 未实现完整目录删除／项目迁移 UI、AST 分析器、全仓索引、自动运行项目或跨仓一致性快照。

## 安装与兼容性

目标运行时：**DSH `0.2.0-rc.2`**。无需修改已安装 DSH 的源码，提供原生 Host 插件、独立 preset 与 Client 模块。

构建后本地归档位于 `releases/dsh-code-reading-0.1.1.tgz`。可在 DSH 插件／Bundle 安装界面使用该归档的绝对路径安装并启用；本工程没有安装期脚本，不需要批准依赖构建脚本。不要为不兼容的 DSH 版本盲目授予版本豁免。

卸载／停用不删除阅读档案；保留的旧阅读工具会 fail closed。重新启用在同一 Host 根下复用 store 与锁，避免旧会话和新页面形成双写运行时。普通 DSH 会话不受阅读工具守卫影响。

Client 使用 DSH 原生模块工厂并外置 React。修改本工程后必须重新构建、打包和安装，按安装器提示重启 Host 或刷新 Client；桌面 startup profile 仅刷新页面不足以加载新的 Host。本工程不是替代 Web 服务器，也不承诺已安装桌面版自动热更新。

## 开发与验证

```powershell
# 使用当前 DSH 提供的 Node 和 pnpm，或你的兼容 Node / pnpm。
pnpm install --ignore-scripts
pnpm run build
pnpm test
pnpm run test:browser
pnpm run pack:release
```

浏览器测试默认使用本机 Chrome，可通过 `DSH_TEST_BROWSER` 指定 Chromium 可执行文件。浏览器测试拦截所有 HTTP，验证真实 Client 构建工厂、React 页面与 Mermaid；**这是隔离组件测试，不是绕过当前 DSH 登录的端到端测试，也不会启动替代服务器或调用真实模型**。报告和截图在测试输出目录。

当前已通过 26 项插件回归及 3 项只读日志验收工具回归，并核验重启后既有真实阅读轮次的只读模式、五工具白名单、源码证据、发布、审计和消息归档。多仓同名路径、普通工作区变化及面板重挂载由测试夹具回归；没有为验收追加真实跨仓模型请求。真实轮次与测试范围见 [验收记录](<VALIDATION.md>)。

可设置 `DSH_TEST_ARCHIVE_STATE` 后运行浏览器测试，对已有档案的内嵌 Mermaid 做隔离内容复验。原生 v4 日志使用多帧 zstd；[只读解码器](<scripts/read-session-log.mjs>) 与 [档案验收器](<scripts/verify-reading-archive.mjs>) 需要自带 zstd 支持的 Node 24+，建议使用当前 DSH 的 Node。它们不会发起阅读模型请求、运行项目代码或写入原阅读档案。

测试覆盖：跨仓同名文件、外部仓库／证据拒绝、路径穿越、junction 与硬链接、源码变化、CAS、发布幂等与凭据冲突、完整事件前缀重放、启停共享运行时、阶段／提问准入、模型提供方错标、Markdown／Mermaid 自动外连回归，以及页面阶段和文件结果仓库身份。

工程结构：[Host](<src/index.mjs>)、[阅读 preset](<src/preset.mjs>)、[档案与锁](<src/store.mjs>)、[文件边界](<src/filesystem.mjs>)、[页面](<src/client/index.jsx>)、[完整可复用 skill](<skills/code-tutor/SKILL.md>)。[参考提取器](<scripts/extract-reference.py>) 只读提取本机 ASAR 的参考模块，不修改安装目录；参考模块不会打包发布。
